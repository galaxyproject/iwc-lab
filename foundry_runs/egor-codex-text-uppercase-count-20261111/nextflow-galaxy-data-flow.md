# Nextflow to Galaxy data flow

## Inputs and outputs

Основание: `summary-nextflow.json`, `nextflow-galaxy-reference-data.md`, `nextflow-galaxy-interface.md` и унаследованный журнал обязательств. Вход `text_input`: один обязательный dataset `txt`. Выходы: одиночные dataset `uppercase_text` и `line_count_summary`, оба текстовые.

## Abstract DAG

`text_input -> uppercase -> count_lines`

Результат `uppercase` одновременно публикуется как `uppercase_text` и передается в `count_lines`. Результат `count_lines` публикуется как `line_count_summary`. Имена реальных портов инструментов определит этап реализации; здесь они не выдумываются.

## Nodes and tool needs

| Node | Source | Required operation | Shape |
|---|---|---|---|
| `uppercase` | Процесс `UPPERCASE` | Изменить только ASCII-буквы a-z на A-Z, сохранив остальные байты, порядок, пустые строки и наличие последнего перевода строки. Это действие исходного `LC_ALL=C tr`. | File -> File |
| `count_lines` | Процесс `COUNT_LINES` | Подсчитать записи как AWK `NR`, включая непустую последнюю запись без перевода строки; сохранить точную UTF-8 подпись `Количество строк: `, число и перевод строки. Для пустого файла число равно 0. | File -> File |

Оба узла обязательны. Счетчик получает преобразованный файл, а не первоначальный вход. Проверка только числа строк не доказывает правильность первого шага; тесты должны сравнить оба результата с реальными эталонами Nextflow.

## Operators and Galaxy idioms

`Channel.fromPath` подает один выбранный файл; присваивание `upper = UPPERCASE(source)` и вызов `COUNT_LINES(upper)` становятся прямыми связями dataset. Не требуются коллекции, map-over, paired/list формы, Apply Rules, join, fan-in, фильтрация или дополнительные преобразования формы.

В этой проверке рассматривается один выбранный файл, как в исходном примере. Многофайловые glob-входы не являются проверенным сценарием этого запуска.

## Confidence and handoff

Высокая уверенность в последовательности двух операций и File-формах: они явно заданы процессами и исправленной source-grounded сводкой. Уверенность в datatype `txt` средняя: это текстовый контракт с проверяемым содержимым, а не специализированный табличный формат. Конкретные обертки, версии и имена портов остаются задаче discovery/implementation.

Параметр публикации `outdir` исключен из Galaxy-интерфейса ранее; решение и запись `drop-outdir-publication-interface` сохраняются без изменения. Оба процесса и оба результата сохранены. Справочные данные не используются.

## Open obligations

Передан исходный журнал целиком; новых обязательств или вычислительных блокеров этот этап не добавляет. При выборе оберток необходимо проверить их реальные текстовые и Unicode-семантики, а не только совпадение формата `txt`.

## Feedback

no feedback: использованные заметки покрывают прямую последовательность File -> File без коллекций и условных ветвей.
