# Происхождение входов и точные сравнения

Три входа и шесть эталонных файлов скопированы из файлов реальных запусков Nextflow, без нормализации и без чтения результатов Galaxy. В test-data/manifest.json сохранены исходные пути, длины и SHA-256 всех девяти файлов.

В YAML входы переданы через class: File / contents. Перед записью каждый текст декодирован как UTF-8 и повторно закодирован; байты проверены на точное совпадение. Включены пустая строка и строка без завершающего LF. Сохраненные локальные файлы остаются доступными для проверки происхождения.

Причина выбора contents: установленный Planemo 0.75.48 вызывает stage_in с глобальным to_posix_lines=True для Galaxy. В galaxy-tool-util 26.1.2 путь FileUploadTarget передает это глобальное значение в fetch payload, не используя одноименное поле самого File. Ветка FileLiteralTarget для contents явно задает to_posix_lines=False. Это подтверждено проверкой исходного кода и пробного payload, а не ошибкой запущенного workflow. Ни Planemo, ни Galaxy ради обхода не изменялись.

Каждый выход проверяется по ожидаемому файлу без допуска diff и по SHA-256, включая последний LF. Тип выхода проверяется как txt. Значения получены из Nextflow в этом запуске; исходных nf-test assertions нет. Реальная проверка через Galaxy выполняется родительским этапом run-workflow-test, ее результат описывает workflow-test-result.json. Само прохождение статической проверки не означает успешного исполнения.
