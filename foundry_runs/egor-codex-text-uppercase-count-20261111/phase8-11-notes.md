# Фазы 8-11: данные, план тестов и статические проверки

Фаза 8 разрешила только вход выбранного исходного кандидата `pipeline-defaults`: `source/data/words.txt` для публичной метки `text_input`. Проверена фактическая SHA-1 файла из `summary-nextflow.json`. Публичный URL не объявлен; файл остается локальным артефактом с происхождением. Поиск другого набора данных не требовался. Проверка `foundry validate-test-data-refs` завершилась успешно.

Фаза 9 сохраняет выбранный исходный случай и добавляет два явно авторских граничных случая: UTF-8 с последней строкой без LF и пустой файл. Оба дополнительных входа также исполнены настоящим Nextflow до авторства Galaxy-тестов. В исходнике нет nf-test, snapshot или исходных ожидаемых файлов. Поэтому `source.derived_from` и случаи имеют `intent`, конкретные ожидаемые значения имеют `fixture-derived`, а план содержит предупреждение `no-upstream-expected-outputs`. Это отделяет результаты данного запуска от исходных assertions. Конкретные метки прочитаны из финального workflow, включая допустимую списочную форму gxformat2. Проверка `foundry validate-galaxy-workflow-test-plan` завершилась успешно.

Фаза 10 скопировала три входа и шесть ожидаемых результатов из реальных файлов Nextflow в `test-data/`. `manifest.json` содержит происхождение, размер и SHA-256 каждого файла. Ожидаемые результаты не вычисляются из Galaxy. Входы передаются в companion YAML через `class: File` / `contents`, включая пустую строку. Обратное чтение сохраненного YAML подтвердило побайтовое совпадение с исходными входами: 22 байта для исходного случая, 21 байт без последнего LF и 0 байт для пустого входа. Результаты находятся в `logs/phase10-input-roundtrip.json`. `gxwf validate-tests` с финальным workflow вернул `valid:true`, список ошибок пуст.

Для этих трех маленьких UTF-8 входов `contents` выбран осознанно. Установленные Planemo 0.75.48 и galaxy-tool-util 26.1.2 не передают свойство `to_posix_lines:false` конкретного `FileUploadTarget` поверх глобального флага Galaxy. Ветка `FileLiteralTarget` явно использует `false`. Проверка исходного кода и пробного payload относится к подготовке загрузки; она не объявлена ошибкой исполненного Galaxy job. Подробность находится в `phase10-test-notes.md`.

Оба выхода каждого случая сравниваются с соответствующим эталонным файлом без допуска различий, дополнительно проверяются SHA-256 и тип `txt`. Это проверяет ASCII-преобразование, неизменность не-ASCII-байтов, отсутствие последнего LF и число записей AWK, включая ноль для пустого входа. Все 6 ожидаемых файлов имеют независимое от Galaxy происхождение.

Фаза 11 выполнила терминальный `gxwf validate` с `--offline --strict --connections --json` на заполненном кэше двух точных инструментов. Результат: 2 проверенных инструмента, 0 ошибок, 0 пропущенных проверок; обе связи также корректны. Финальный отчет находится в `galaxy-workflow-validation-result.json`, исходный JSON CLI в `logs/phase11-gxwf-validation.json`.

Статические проверки не доказывают успешный запуск. На момент завершения этих фаз ни один Galaxy job еще не был запущен. Runtime gate из `implement-galaxy-workflow-test` выполняется родителем вместе с выделенным следующим этапом `run-workflow-test` на том же companion-файле; его честный итог и идентификаторы задает `workflow-test-result.json`.

Набор ограничен одним текстовым файлом и двумя последовательными процессами. Это учебный случай с настоящим исполнением, а не проверка многообразия nf-core или научной корректности биологического анализа. Поведение `params.outdir` заменяется управляемыми Galaxy datasets; multi-file glob не проверялся.

Результаты обратной связи:

- Фаза 8: `no feedback`.
- Фаза 9: `nextflow-test-plan-assumes-nf-test-evidence`. Безусловное требование Mold использовать `source.derived_from: test-evidence` противоречит выбранному случаю без исходных assertions. Текущий main проверен: SHA-256 совпадает с cast. Поиск по открытым и закрытым issues не выявил точного дубля. Закрытый #679 исправил уровень отдельных assertion, но не оставшуюся безусловную установку на уровне source. Открытый #793 относится к выбору кандидата и полю snapshot, а не к отсутствию исходных тестов.
- Фаза 10: `galaxy-stager-ignores-file-newline-override`. Наблюдение относится к Planemo/galaxy-tool-util и к содержимому payload до запуска. Для маленьких данных сохранен обход через `contents` без изменения установленного фреймворка. Поиск в Foundry по `to_posix_lines` и `newline Planemo` не нашел дублей.
- Фаза 11: `no feedback`.

Ни один новый GitHub issue или комментарий в ходе этих фаз не опубликован. Черновики обратной связи остаются материалом отчета запуска.
