# Проверка фактического исполнения Galaxy

Итог: `pass`. Planemo 0.75.48 выполнил три теста в настоящем локальном Galaxy 26.1.3.dev0. Все шесть вычислительных jobs имеют `state=ok`, `exit_code=0`; `copied_from_job_id` не задан. Пропусков, ошибок assertions и execution problems нет. Состояние invocation в API сохранено как `scheduled`, история имеет `ok`; оно не переименовано в выдуманное состояние `complete`.

Каждый тест сравнивает оба результата с файлами настоящего запуска исходного Nextflow: точный файл без допуска различий и SHA-256. Независимая сверка сохраненных фактических скачиваний дала 6/6 совпадений. Все три загруженных входа также побайтово совпали с исходными fixtures. Идентичность скачиваний установлена по UUID из реальных jobs, а не по совпадению ожидаемого содержимого.

Свидетельства: `workflow-test-result.json`, `reports/planemo-test-output.json`, `galaxy-results/comparison.json`, шесть файлов в `galaxy-results/`. Локальный сервер остановлен Planemo после завершения; его IDs оставлены как свидетельство данного временного экземпляра.

## Различение ошибки среды и workflow

Первая попытка дошла до загрузки данных и остановилась в Celery multiprocessing forkserver: `OSError: AF_UNIX path too long`. Длинный TMPDIR задачи превышал ограничение Unix-сокета macOS. Собственный процесс Planemo прерван SIGINT; вычислительные шаги workflow еще не запускались. Структурированного тестового отчета нет. Журнал и execution record сохранены в `reports/previous-executions/`.

Перед второй попыткой изменен только TMPDIR на короткий сохраняемый каталог. Workflow, test file, эталоны и версии инструментов не менялись. Вторая попытка завершилась с кодом 0. Первая попытка не названа ни успешным тестом, ни дефектом содержимого workflow.

## Строгость проверки

Проверены обычный текст из трех строк, UTF-8 с последней строкой без LF и пустой файл. ASCII-транслитерация sed сохраняет не-ASCII-байты; gawk сохраняет счетчик NR и точную русскую подпись через ASCII-безопасные октальные UTF-8-последовательности. Assertions не ослаблялись.

Поле `ftype: txt` в клиентском checker само по себе не доказывает datatype HDA. Поэтому все шесть фактических выходов дополнительно проверены чтением сохраненной базы Galaxy в режиме `mode=ro`: `extension=txt`, `state=ok`, размер совпадает. Выборка без учетных данных находится в `reports/galaxy-dataset-metadata.json`.

Ошибок содержимого, jobs, invocation, коллекций или assertions после исправления среды не наблюдалось. Коллекции этим одиночным текстовым workflow не проверяются. Воспроизведение большого nf-core pipeline, других платформ или всех возможных текстовых байтов из этого результата не следует.

Feedback pass этапа 13: `no feedback`. Ошибка TMPDIR относится к нашей конфигурации среды; исправление upstream не заявляется.
