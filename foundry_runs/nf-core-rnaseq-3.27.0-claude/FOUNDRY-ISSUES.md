## Phase 6 — nextflow-summary-to-galaxy-template

26. **Draft's map-form requirement is documented only by example, and a mis-shaped draft fails with an unreadable error (real usability bug).** The draft contract requires `inputs:` and `steps:` as maps keyed by id, while native format2 uses a list for `steps:` (and either form for `inputs:`); the format note shows the map form only inside its one example, never as a stated rule. The first emitted draft (list-shaped) failed with: one structure error whose "message" is the **entire zod schema plus the full JSON echo of the document — 113 KB for a single wrong shape** — cascading into 78 errors including every step reported as "references unknown step," with no pointer at the offending field. Parse-level errors (line:col, e.g. an unquoted `STAR:` colon) are good; schema-level errors are unusable without post-processing the JSON report.
27. **Inter-brief inconsistency passed silently through four phases.** The interface brief (phase 3) pins `aligner` restrictions `[star_salmon, star_rsem, hisat2, bowtie2_salmon]`, but the data-flow brief (phase 4) wires only the STAR and HISAT2 branches — no Bowtie2 alignment step, index build, or fan-in appears anywhere in Tier 3, and no ledger entry or user-review flag records dropping it. Nothing in the pipeline cross-checks briefs against each other or against the interface (the ledger is threaded forward but never diffed). The template caught it only because the enum was re-read when wiring the fan-in; an executor trusting the data-flow tier list verbatim would ship a dead enum value. Branch restored; discovery `bowtie2-salmon-branch-omitted-in-data-flow`.
28. **The per-sample strandedness computability gap surfaces only at template time.** Neither the interface nor the data-flow brief flags that per-sample strandedness cannot bind to a map-over step param: the phase-4 `metadata-reattachment-bridge` decision implies a tabular→param join that gxformat2 has no affordance for, and featureCounts' `-s` / Salmon's `--libType` are single params on per-sample map-over steps (the IWC corpus is uniformly workflow-level here, so no exemplar rescues it). The gap was discovered while wiring the draft and is now the blocking ledger entry `per-sample-strandedness-param-unbindable` — i.e. the phase that owns data-flow design approved a disposition the output contract cannot represent, and the format note's resolution tiers offer no place to express it beyond `_plan_*` prose.
29. **`--concrete` reads green while validating nothing, and resolved steps with deferred upstreams vanish from the projection.** The draft carries 4 Resolved-tier `__FLATTEN__` steps (concrete tool_id/version/state), yet `draft-validate --concrete` reports `Concrete: OK / Tool state: 0 ok, 0 fail, 0 skip`: `draft-extract` drops them because their input edges point at TODO ports of deferred producers, so the concrete subset is empty (`steps: {}`). Cascade semantics are defensible (a concrete workflow with an edge to a nonexistent step would be invalid) and the docs warn not to over-read early-loop runs — but the human-readable output does not distinguish "nothing concrete yet" from "concrete and clean," and the survey line (260 TODOs / 52 planning steps) is the only real signal.

The template added ledger entry `kallisto-route-not-wired-into-tximport` rather than inventing a merge step — the kind of completeness question (every enum route must terminate in every declared output, or the gap must be recorded) that no phase instruction asks.

## Phase 7 — advance-galaxy-draft-step loop (in progress; 3 iterations executed, 53 drafty steps remain)

31. **The heavy-index build-on-absence posture is systematically unrealizable for Bowtie2 — and the first three loop iterations all hit it.** `draft-next-step` picks alphabetically, so the loop front-loaded `build_bbsplit_index`, `build_bowtie2_index`, `build_bowtie2_rrna_index`. Recorded as `reads-path-fan-in-starvation` (open). The phase-4 decision `enum-branches-as-when-gated-subworkflows` has no pass-through recipe for the all-skipped case.

## Phase 7 — conclusion (batch mode, operator-mandated)

The loop was completed in batch mode at the user's request (4 mutation batches with one validation per batch instead of the skill's per-edit validation — that protocol deviation is itself finding-worthy: per-edit validation multiplies wall-clock by ~6x on a 47-step draft).

35. **A genuine cycle passed topology validation.** `umi_extract` consumed `rrna_filtered_reads/TODO_value` while the three rRNA filters consumed `umi_extract/TODO_reads` — a directed cycle — and `draft-validate` reported 0 topology errors through six prior green runs. The cycle was introduced by the phase-6 repair that re-wired the rRNA branch (the same repair that fixed finding #33b) and went unnoticed because the validator checks port existence, not acyclicity. Source order is trim(→umi extract) → rRNA removal → downstream; fixed in batch A.

Each iteration of the per-step protocol would have hit these one at a time; the batch run needed a purpose-written reference-sweep map (47 entries) as a new, undocumented artifact type.
37. **`--concrete`'s tool_state count stayed at 12 while the draft reached 36 Resolved steps.** When-guarded steps are excluded from the concrete projection even when fully resolved with valid state (extends finding #29: the concrete projection under-reports progress in a condition-heavy pipeline — i.e. in exactly the pipelines this Foundry targets).

Cure (our-artifact fix, applied to `galaxy-workflow.ga`): rewrite all 14 tool steps' `tool_id` to `<tool_id>/<tool_version>` (e.g. `.../devteam/fastqc/fastqc/0.74+galaxy1`), matching the installed guids; verified post-edit that the injected `tool_shed_repository` blocks survive.
